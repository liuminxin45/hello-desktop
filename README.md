# Hello Desktop

**面向 Windows，学习如何独立设计、交付和维护一个桌面客户端。**

界面能跑起来之后，工程问题才刚开始：为什么换台电脑就缺 DLL？为什么窗口卡住了，CPU 却不高？一次更新如何保住用户数据？只拿到客户的 dump，怎样继续调查？提供给其他团队的 SDK，如何在升级后仍然可用？

本教程围绕这些问题展开，目标读者是已经会一门编程语言，希望从“能实现功能”走向“能负责产品交付和长期维护”的开发者。

## 先确定学习目标

“Windows 上开发的一切”足以写成一套丛书。这里先选择一个可交付的目标：**围绕同一个 Windows 客户端，掌握系统机制、界面交互、模块边界、故障诊断和版本交付，并能解释自己的取舍。**

高级工程师的成长不等于多学几套 UI 框架。我们用以下任务检验能力：

- 能把一个需求拆成界面、后台任务、数据、原生模块和交付边界。
- 能通过证据调查“打不开、卡住、崩溃、数据损坏、升级失败”。
- 能设计可维护的 API、C ABI 和 SDK，并验证兼容性。
- 能从干净环境构建、安装、升级、卸载，保留产物与诊断信息。
- 能审查 AI 生成的改动，说明验证结果及其局限。

这些任务用于组织教程，不对应所有公司的职级标准，也不能代替真实项目经验。

## 框架怎么安排

C# 是语言；WPF、WinForms、WinUI 是不同的界面技术。Qt 可以分别选择 Widgets 与 Quick/QML，Electron 也需要理解自己的进程与权限边界。框架名称不在同一抽象层，不能直接排列成一份必学清单。

主线以 **C# / .NET / WPF** 解释界面机制，以小型 C 兼容接口解释原生边界；附带的原生库用 C11 实现，头文件可由 C/C++ 调用。这个安排便于把 Windows 界面和原生互操作串起来，是教学选择，不是对所有新项目的统一选型。托管与原生实验的工具链见[环境说明](examples/README.md)。

Qt、Electron 和 WinUI 提供平行的学习路线；WinForms、MFC 与现有系统维护单列路线。每位读者先完整走通一条，再迁移同一个功能，不要求把所有框架各学一遍。

## 贯穿案例：桌面任务工作台

从“选择目录，执行文件分析并展示结果”开始，逐步加入后台任务与取消、菜单与托盘、SQLite 历史记录、原生分析 DLL、可单独使用的 SDK、日志与故障采集、安装升级和 CI。

核心任务保持为本地文件分析。设备接入、图形渲染、音视频、内核驱动、完整逆向工程和在产品中集成 AI，放在专题扩展；不把它们全部塞进同一个演示程序。

## 运行检查

安装 Node.js 24.19.x 后，在仓库根目录运行 `npm test`，检查课程结构、本地链接并运行 SQLite 实验。无需安装 npm 第三方包。托管实验需要 .NET 10 SDK，原生实验还需要 CMake 与 Windows C/C++ 工具链，完整命令见[实验说明](examples/README.md)。
