# 学习方法与验收

## 开始前需要什么

这条主线面向已经会一门语言的开发者。开始前，至少能：

- 使用函数、类型、集合、异常和文件读写完成一个小工具。
- 读懂自己所选语言的对象生命周期、回调与异步基础。
- 用 Git 保存改动，从命令行构建项目，设置断点并查看调用栈。
- 说明输入、输出和失败条件，编写少量能够发现错误的测试。

不具备这些能力时，先做“读取目录并生成统计报告”的命令行小程序，再用一种 UI 框架给它加窗口。不要同时从零学习 C++、C#、JavaScript 和所有框架。

原生互操作章节会提供最小 C/C++ 补课：指针、布局、内存归属、编译链接和导出函数；不会将整门 C++ 语言课塞进 SDK 章节。已有相关能力可以跳过补课。

## 一章怎样学完

先预测结果，再运行或观察，最后解释差异。每章留下三个东西：一个可检查的产物，一段机制与取舍说明，一次条件变化后的验证。

例如学习 DLL，不以“知道 DLL 是动态库”为终点。应当能解释它由谁加载、依赖什么、为何加载失败；制造一次缺失依赖的故障，找到证据，再在干净环境验证修复。

只看文章时也可以做推演题，但阅读理解与实际工程验证分别记录。没有运行过的安装、迁移、崩溃采集和兼容性检查，不标为实验通过。

## 用六个问题学任何框架

1. 程序从哪里开始，窗口关闭后什么条件决定进程退出？
2. 事件在哪个线程或进程处理，耗时工作应该在哪里执行？
3. UI 状态和业务状态分别归谁，变化怎样传递？
4. 对象、句柄、连接和回调怎样结束生命周期？
5. 文件、数据库、系统 API 和原生 SDK 怎样跨越边界？
6. 换一台干净电脑，怎样运行、诊断和升级？

这些问题会复用，但答案不会预设相同。官方最小样例用来定位入口；源码和调试用来回答具体疑问；API 索引用来补细节。

## 分阶段留下证据

| 阶段 | 必须能展示什么 | 常见理解缺口 |
| --- | --- | --- |
| 01–04 | 干净构建记录、启动与事件时序、资源归属 | 把窗口、线程、进程混为一谈 |
| 05–08 | 执行/取消/关闭状态、键盘与 DPI 检查、框架取舍 | 只会正常路径，无法解释回调晚到 |
| 09–12 | 独立 SDK 调用方、依赖图、契约与兼容记录 | 交出 DLL 就当作 SDK 已完成 |
| 13–16 | 数据迁移和恢复记录、权限表、通信失败处理 | 只验证开发者管理员账号 |
| 17–20 | 复现、证据、假设、对照实验及剩余不确定性 | 把一张调用栈或反编译片段直接当根因 |
| 21–24 | 安装升级产物、源码/符号映射、流水线结果、AI 改动审核 | 能本地构建，却无法交付和调查客户问题 |

“能说出概念”“能完成实验”“能在陌生故障中迁移应用”是三个不同阶段。高级能力更依赖最后一项，并需要持续的真实项目经验。

## AI 怎样参与

可以让 AI 解释陌生代码、提出调查假设、起草样例、补充测试和检查遗漏。给它的问题应包含预期、实际、最小复现和经过脱敏的必要证据。

对生成结果追问：接口真实存在吗？线程和生命周期正确吗？资源由谁释放？ABI 是否一致？失败后状态如何？引用的是哪个版本的文档？最终根据自己运行的检查结果判断，而不是根据回答是否流畅判断。

练习保留一份“曾经很像正确答案，但被证据否定”的记录。它能检验你是否掌握判断方法，也能防止把 AI 生成速度误当作工程交付能力。

## 给已有经验的读者

先挑战阶段验收。已经能提供完整证据的部分可以略读；没有解决过的取消竞态、ABI 兼容、dump 分析、数据迁移和升级失败，选一个补齐。

学习范围由承担的责任决定。做工业设备客户端、内容编辑器和企业管理工具，公共主线相似，深入方向不同；不需要为了“高级”把所有专题同时学完。
