# 02 从源码到一次可重复的运行

上一章确定了程序要承担的责任。现在把工程交给同事，对方双击 EXE 却打不开。你机器上的 IDE、SDK、运行时和环境变量，可能替你补齐了并未进入交付包的条件。

本章区分构建条件与运行条件。目标是让别人依据说明，从干净目录构建并运行同一个实验。

## SDK、工具链与运行时不是一回事

SDK 提供开发所需的工具与引用；运行时负责执行相应类型的程序。安装了 .NET Runtime，不代表安装了能编译工程的 .NET SDK。先分别观察：

```powershell
dotnet --list-sdks
dotnet --list-runtimes
```

在本仓库的托管实验中，源码先编译为程序集，运行时再执行它。原生 C/C++ 实验通常经历预处理、编译和链接，产生机器代码及相应产物；链接器需要解决模块之间的符号关系。不要因为扩展名同为 `.dll` 就认为托管程序集与原生 DLL 可按相同方式调用。

构建系统还决定配置和架构。`Release` 通常启用适合交付的优化；它不等于“绝对没有调试信息”。优化可能使局部变量和源代码行与执行位置的对应更复杂，因此要保存该版本实际生成的符号。

## 运行入口也有条件

| 选择 | 运行机器需要什么 | 代价 |
| --- | --- | --- |
| .NET 框架依赖发布 | 兼容的目标运行时 | 包较小，需管理运行时安装 |
| .NET 自包含发布 | 包内的 .NET 运行时及其系统前提 | 包较大，运行时更新由产品承担 |
| 原生程序 | 匹配的系统、架构及实际运行库依赖 | 需要清点直接与间接依赖 |

自包含不会自动捆入所有第三方 DLL，也不会让仅面向 Windows 的 UI 跨平台。单文件发布和自包含又是不同的选择。

同一进程中加载的原生模块通常要与进程架构匹配。64 位操作系统能运行某些 32 位程序，不意味着 64 位进程可以直接加载 32 位 DLL。`AnyCPU` 也不能替原生依赖做这个决定。

## 第一次可重复构建

本书托管实验面向 .NET 10，仓库记录 SDK 选择；安装方法和已验证环境见[实验说明](../../examples/README.md)。在仓库根目录运行：

```powershell
dotnet run --project examples/managed/Workbench.Checks -c Release
dotnet run --project examples/managed/Workbench.Cli -c Release -- scan docs
```

第一条验证分析器的约定，第二条分析仓库里的文档目录。数字会随文件变化，不提供一个假定永远相同的输出。终端当前目录决定相对路径的含义。

要观察最小 WPF 工程，可以在自己的练习目录执行：

```powershell
dotnet new wpf -n WorkbenchApp
dotnet build WorkbenchApp -c Release
dotnet run --project WorkbenchApp
```

这个练习需要 Windows 和适用的 SDK。项目名避免采用 `Window` 这样的框架类型名作为命名空间尾段，以免名称解析冲突。它生成默认窗口，不会自动接入本书后续的分析器、SDK 或安装功能。先在启动位置和一个事件处理器设置断点，确认自己知道代码从哪里进入。

## 记录环境，比复制整个开发目录更有效

留下操作系统与架构、源码提交、SDK/编译器版本、配置、构建命令、产物目录和依赖清单。不要提交 `bin`、`obj` 或机器绝对路径来代替这些信息。需要依赖包时，再把锁定与恢复策略加入构建契约。

“可重复执行构建”指相同说明能够再次生成可用产物；“字节级可复现”还要求处理时间戳、路径、签名等非确定因素。首版先做到前者，并保留产物对应关系，不提前承诺后者。

## 动手：做一次干净检出

把已提交源码检出到新目录，只按实验说明运行。先记录 `--list-sdks`，再构建。遇到缺失 SDK、找不到 DLL 或架构不符时，不向系统目录随手复制文件；记录缺的究竟是构建工具、运行时还是产品依赖。

验收是另一目录可构建、可运行，且能从说明中找到缺失条件。当前作者实际验证的范围见[验证记录](../../editorial/validation.md)，读者机器上的结果需要另行记录。

## 检查理解

**装了 .NET Runtime，为什么 `dotnet build` 仍失败？** 运行程序集与编译工程使用不同组件。先检查 SDK 列表，不能仅凭系统中存在 `dotnet.exe` 判断开发环境齐全。

**Release 构建崩溃后还需要 PDB 吗？** 需要保存匹配该产物的符号，尤其是优化后的调用位置调查。重新用“相同版本号”编译的 PDB，不一定匹配客户正在运行的二进制。
